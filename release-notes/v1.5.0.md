Everything PingerPlot measures is recorded, with a History page to look back through it. Reroutes and DNS moves are tracked, every router shows where it is and whose network it's on, and the map says where on the path the trouble is.

**On 1.4.x?** PingerPlot offers this update by itself (or ⋯ → **Check for updates**): click **Install and restart**. Otherwise: [`PingerPlot-Setup.exe`](https://github.com/jamesccupps/PingerPlot/releases/download/v1.5.0/PingerPlot-Setup.exe) (installs for your Windows user, no admin prompt) or [`PingerPlot-win64.zip`](https://github.com/jamesccupps/PingerPlot/releases/download/v1.5.0/PingerPlot-win64.zip) (portable). Scoop: `scoop update pingerplot`. On Linux: `pipx reinstall pingerplot`. The downloads are code-signed by James Cupps; `SHA256SUMS.txt` lists every file's hash.

### Everything recorded

- **History, on by default, nothing to set up.** Every probe and the router that answered it, per-minute stats for each hop, every event, and every route go into one database on your PC (`history\history.sqlite3` in the settings folder), from the window and the headless runner alike. Nothing is sent anywhere.
- **Settings → Recording** turns it off, sets how long each part is kept (probes 7 days, summaries and events a year) and the size limit (1 GB), picks what's recorded, opens the folder or clears it. Changes apply at once, to running targets too.
- **Robust:** writes happen in the background so probing never waits; a crash loses at most a second; a damaged file is set aside and a new one started; a full disk is a warning in Events, not silent loss. A webhook address is never written to it.

### The History page

Any hour of the last year for a target, stepped back and forth: latency and loss with the route in use as a color band and reroutes and alerts marked; **Routes**, with how the destination did on each, so the bad path stands out; **Hops**, every router seen at each hop and how it did; **Events**, filtered and searched; and CSV export of any range. A target's right-click menu has **Show history**.

### Reroutes and moves

- **A reroute is reported once, and load balancing isn't reported as one.** A router has to hold a hop for 3 rounds to count as a reroute; routers that take turns at a hop are noted once as load balancing.
- **A name that moves is followed.** A target given by name is looked up again every 5 minutes; if DNS sends you to a different server, that's an event and PingerPlot traces the route to the new address. Round-robin DNS that only reshuffles isn't a move.

### Where routers are, and where the trouble is

- **Location and Network columns**, and **Details…** on a hop's right-click menu: where the router is by its name and by the IP database (each labeled), whose network it's on, and every router seen at that hop in the last day.
- **A router's city from its name** (`chcgil`, `dfw01`, `Dallas1`), offline. For backbone routers that's usually right where IP geolocation isn't.
- **Under the map, where the trouble is:** each place on the path, the delay it adds and the loss that starts there and carries to the destination, with a one-line verdict. Loss that stops at a router is that router ignoring pings and isn't blamed. Routers are placed by their name first, and the target's other routes from the last day are dashed underneath.

### Privacy

Router lookups now run while monitoring, not only while the Map is open, so the tables and history can say where routers are. Only public router addresses go to ipwho.is (never private or LAN ones), each about once a month, at most 500 a day. **Settings → Look up where routers are** turns it off; the Map then asks only while it's open, as before.
