Fixes from an outside review: a History export that no longer freezes the window, UDP probes that stay on the port you set, and sturdier handling of damaged or hand-edited files.

**On 1.4.x or 1.5.x?** PingerPlot offers this update by itself (or ⋯ → **Check for updates**): click **Install and restart**. If you're running it as administrator, start it normally first; see below. Otherwise: [`PingerPlot-Setup.exe`](https://github.com/jamesccupps/PingerPlot/releases/download/v1.5.2/PingerPlot-Setup.exe) (installs for your Windows user, no admin prompt) or [`PingerPlot-win64.zip`](https://github.com/jamesccupps/PingerPlot/releases/download/v1.5.2/PingerPlot-win64.zip) (portable). Scoop: `scoop update pingerplot`. On Linux: `pipx reinstall pingerplot`. The downloads are code-signed by James Cupps; `SHA256SUMS.txt` lists every file's hash.

### Changed

- **UDP: every probe goes to the port you set.** The first trace did, but every round after it sent each hop to a different port, so a firewall that passes only your port let the trace through and then dropped the rounds. Replies are now matched the way TCP mode matches them, which also makes a forged reply much harder to pass off.
- **Running as administrator, PingerPlot doesn't install updates in place.** It still tells you a new version is out, and asks you to start PingerPlot normally to install it. The download waits in your own temp folder, where any program running as you could swap it before it ran with administrator rights. [SECURITY.md](https://github.com/jamesccupps/PingerPlot/blob/main/SECURITY.md) now says what an administrator copy trusts.

### Fixed

- **History → Export → "Every probe" froze the window**, for many seconds with a week of history, and used gigabytes of memory. It now runs in the background, counts rows as it goes, and writes as it reads. A failed export leaves no half-written file, and events exports are no longer cut off at 100,000 rows.
- **Opening Details could hold the window for up to 2 seconds.**
- **A hand-edited settings.json with a number where text belongs stopped PingerPlot opening.** That target now falls back to the defaults.
- **A session file with impossible values** (NaN, Infinity, a time far in the future) broke the Events view of its tab. Such values are now dropped when it opens.
- **The history could stop recording without saying so** after a damaged or edited file. Problems are now reported in Events and recording carries on.
- On a busy network, a TCP or UDP round could run past its timeout.
- On Linux and macOS, another host's ping reply could count as the target answering.
- Odd answers from the location service, or a damaged lookup cache, could raise errors in the hop table.
- Router names with control characters reached the console and CSVs as they were.
- Headless: `"final_hop_only": "false"` turned it on, and a `status_interval` that isn't a number crashed the runner. Both are now refused with the reason.
- The privacy text said only routers' addresses go to ipwho.is. The destination's own address does too, and the README, the website and Settings now say so.

The full list is in the [CHANGELOG](https://github.com/jamesccupps/PingerPlot/blob/main/CHANGELOG.md).
