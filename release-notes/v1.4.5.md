PingerPlot installs with Scoop, and Start with Windows works for a Scoop copy.

**On 1.4.x?** PingerPlot offers this update by itself (or ⋯ → **Check for updates**): click **Install and restart**. Otherwise: [`PingerPlot-Setup.exe`](https://github.com/jamesccupps/PingerPlot/releases/download/v1.4.5/PingerPlot-Setup.exe) (installs for your Windows user, no admin prompt) or [`PingerPlot-win64.zip`](https://github.com/jamesccupps/PingerPlot/releases/download/v1.4.5/PingerPlot-win64.zip) (portable). Scoop: `scoop update pingerplot`. On Linux there's nothing new. The downloads are code-signed by James Cupps; `SHA256SUMS.txt` lists every file's hash.

### Install with Scoop

```powershell
scoop bucket add jamesccupps https://github.com/jamesccupps/scoop-bucket
scoop install jamesccupps/pingerplot
```

New to Scoop? See [scoop.sh](https://scoop.sh).

### Fixed

- **Start with Windows on a Scoop install** pointed at that version's folder, so after `scoop update` it started the old version at sign-in, and after `scoop cleanup` nothing. It now follows Scoop's `current` link. If you turned it on in 1.4.4, this version corrects it the first time it starts.
- The release workflow can no longer replace a file on a release that's already published: Scoop and winget check every download against the hash they recorded.

The full list is in the [CHANGELOG](https://github.com/jamesccupps/PingerPlot/blob/main/CHANGELOG.md).
