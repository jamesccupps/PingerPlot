### Fixed

- **TCP mode sent most probes two or three times.** Each hop's connection stayed open until the whole round ended, and Windows kept resending its SYN after the router had already answered. A round with one silent hop lasts 3 s, so most hops went out two or three times. A hop's connection now closes as soon as it answers, which roughly halves the traffic a TCP trace sends.
- **An interval shorter than the reply timeout had no effect, and nothing said so.** Each round waits for hops that don't answer, so in TCP mode (which waits at least 3 s) "every 1 s" ran every 3 s. The Events tab now says so when a target starts.

### Which mode to leave running

The README now says: ICMP. A TCP trace sends each hop from its own port, so on load-balanced links neighboring hops can take different paths, and a SYN per hop per round can look like a SYN flood to intrusion detection. Use TCP to check a particular service, or to trace a path that blocks ICMP.
